# Table-stakes read

The Fifty reports. This output judges it.

One question: **of every attribute in the competitive grid, which are table stakes, and which are real differentiators?**

## Where it sits

This is the mechanical half of April Dunford's positioning sequence. Her first two components are the competition, then differentiators — and she is explicit that an attribute is only a differentiator when compared against the competition. This output does that comparison by counting. The Positioning output takes what survives and does the rest: value, target customer, category.

So the chain is: **The Fifty** gives the cells. **Table-stakes read** counts them and judges. **Positioning** builds on what's left.

Do not do positioning work here. No category naming, no value narrative. Count and judge. Do not check the client's homepage against the count either. That belongs to the Landing page review.

## Inputs

The attribute list comes first. Kernel drafts it from the client's own pages, in words a buyer would recognise, and the client confirms, edits, drops or adds. The counts come from The Fifty's cells. Buyer validation comes from Voice of customer, Win / loss and public reviews.

The output stays locked until The Fifty is proven. Show what unlocks it and a faded preview of the page.

## The four bands

Count how many competitors hold each attribute, including the client and including the status quo column where it applies.

| Held by | Band | What it means |
|---|---|---|
| All, or all but one | **Table stakes** | You must have it. Having it wins nothing. Stop selling it. |
| Some, but not all | **Contested** | Several have it, nobody owns it. Weak ground for a claim. |
| Only you | **Differentiator candidate** | Might be a differentiator. Not yet. |
| Nobody | **Market gap** | An opening, or a thing nobody wants. The grid cannot tell you which. |

On screen each band shows its count rule beside it: Table stakes (all have it), Contested (some have it), Differentiator candidate (only you), Market gap (none have it).

Set the thresholds from the column count and state them. With six competitors, five or six is table stakes, two to four is contested, one is a differentiator candidate.

## The trap, and buyer validation

**An attribute nobody else has is not automatically an advantage.**

Kano's 1984 model has five categories, and the one that matters here is *indifferent quality* — attributes customers do not care about either way. Most unique attributes are unique because nobody thought they were worth building.

So every differentiator candidate gets a buyer validation mark, and this one cannot come from the grid:

| Mark | Means |
|---|---|
| **Validated** (solid) | Customers said, unprompted, that they care |
| **Partly validated** (half) | Someone said it, but prompted or second-hand |
| **Not yet validated** (dashed) | Nobody has been asked |

Most candidates in an early-stage company come back not yet validated. That is the key finding, not a failure — it means the differentiation story rests on something never tested.

Buyer validation comes from Voice of customer and Win / loss interviews and from public reviews, with the quote shown. This is the one place cross-output evidence is allowed, because the judgment is not possible without it. Name the evidence source on each mark.

## Attributes, not features

Count attributes a buyer would recognise, not internal capabilities. "Halal-screened portfolios" is an attribute. "Screening engine v2" is not.

Twelve to twenty attributes is right. If you have sixty you are listing features.

## Action per band

State it plainly for each band, once:

- **Table stakes** — must be present, must not be sold. Remove from the homepage headline and the first pitch slide. It belongs in a comparison table, not a claim.
- **Contested** — only usable with a proof point that separates you on degree. Without one, drop it.
- **Differentiator candidate, validated** — this is the positioning input. In the app, a button sends it to Positioning.
- **Differentiator candidate, not yet validated** — the test goes in the Assumption log. In the app, a button adds it there.
- **Market gap** — decide whether it is an opening or a dead end. That is a research question, not a positioning one.

## Output structure

Header: `Table-stakes read · N attributes · M competitors · <date>`.

**01 · Attributes by competitor count** — the whole list, sorted, drawn as marks. The bands separated by rules. This is the main visual and the sort order is the argument.

**02 · Differentiator candidates** — each with its buyer validation mark, the quote and its evidence source.

**03 · Key finding** — one sentence, black band.

**04 · Limitations** — the standing limits.

Four sections. Do not add more.

## Drawing rules

- One mark per competitor per attribute. The reader counts, they do not read a percentage.
- Sort by count, descending. The band boundaries are horizontal rules across the page.
- The buyer validation mark sits in its own column, visually separate from the count, so nobody confuses "unique" with "wanted".
- Fill grammar first. Green marks only what is proven: a held attribute with a source, a validated mark, and finished steps.

## Writing rules

- No section subtitles unless they carry information the drawing does not.
- Never write a balanced two-part line. If it has a rhythm or would work on a poster, cut it.
- The key finding is a fact, not a formulation.

## Language

Standard product marketing terms on every label and heading. Never a label built from "who, what, which, where" phrasing.

| Use | Instead of |
|---|---|
| Attributes | What you have, features |
| Table stakes | Everyone has it, price of entry, hygiene factor |
| Contested | Some have it |
| Differentiator candidate | Only you, unique differentiator, moat, USP |
| Market gap | Nobody has it |
| Buyer validation: Validated, Partly validated, Not yet validated | Do buyers care, nobody has been asked |
| Stop selling it | Deprioritise in messaging |
| Competition, competitors | Alternatives |
| Status quo | Never starting, doing nothing |
| Evidence source | Where it came from |
| Key finding, Limitations | The finding, what can't be known |

## Standing rules for every output

- **No invented findings.**
- **No false zeroes.**
- **Name organisations, never individuals**, when the work is confidential.
- **"Not measured" is not an answer.**
- **Read the source, never the snippet.** Every count traces to a cell in The Fifty, and every cell traces to a page someone read in full.
- **If the client's own column is missing, say so and leave it dashed.** A table-stakes read without the client's attribute list is half an output, and it should look like half an output rather than pretending otherwise.
